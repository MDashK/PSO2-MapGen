# Which ICE variant numbers exist for each big chunk - the UnkQ / UnkY of the packet.
#
#   <ModelId> <chunk> = <n>[, <n>...]
#
# UnkP names the big chunk (two ASCII characters little-endian: 13425 = 0x3471 = "q4") and
# UnkQ picks which of its model files to load, stage/sn_<model>/ln_<model>_<chunk>_<n>.ice.
# UnkW / UnkY are the same thing for the second design.
#
# THE VARIANT DOES NOT CHANGE THE MAP.  The generator only ever looks at the chunk NAME - two
# designs with the same name and different variants are one chunk for the candidate pool - so
# this number decides what the piece looks like in game, not where it goes.
#
# The list was not guessed: every line was probed against the client's own data. A file in
# data/win32 is named md5 of its logical path, so for each model and each q* chunk of its .lps
# the numbers 0 to 255 were hashed and the ones that exist kept. The answer is narrow - only
# 80 and 81 are ever present, 80 for every chunk and 81 for seven of them - and the packets
# agree: of the 998 (UnkP,UnkQ)/(UnkW,UnkY) pairs in the 583 captures, 969 use 80 and 29 use
# 81, all of the 81s on 311 q5.
#
# A model or a chunk that is not listed here just gets no suggestions in the tool.
